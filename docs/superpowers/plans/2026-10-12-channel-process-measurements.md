2026-10-12，当前 `codex/channel-pluginization` 候选代码。**本次验证了 SDK 导入隔离、安装目录可运行及进程回收；没有证明多进程能降低总内存或加快正式应用启动。**

## 交付与验收

- 沿用 `plugins/channel/feishu`、`plugins/channel/dingtalk` 两份目录，不新增专用打包器或依赖环境；清单仍为 `publish: false`。

- 修复公共通信层的一处收尾问题：关闭超时或取消原先会取消底层管道仍持有的完成通知，导致 Python 3.13 异步异常。现在保留该通知、维持关闭时间上限，并清理写任务及迟到异常。独立测试先复现失败，再验证修复；异常回收测试另通过故意移除处理行为的反例验证。

## 当前 RSS

每种组合使用全新 Python 进程采样三次，以下每列为中位数，单位 **MiB**。合计列先逐次相加，再取中位数；因此不保证等于两列中位数之和。RSS 相加会重复统计共享页面，**不是实际物理内存**。

| 渠道 | 方式 | 主进程 RSS | 渠道子进程 RSS | 合计 RSS | 停止后主进程 RSS |
| --- | --- | ---: | ---: | ---: | ---: |
| 飞书 | 同进程候选 | 346.8 | 0.0 | 346.8 | 346.7 |
| 飞书 | 子进程候选 | 209.5 | 186.2 | 395.7 | 209.5 |
| 钉钉 | 同进程候选 | 217.6 | 0.0 | 217.6 | 217.6 |
| 钉钉 | 子进程候选 | 209.8 | 82.4 | 292.1 | 209.7 |

- **飞书：**主进程 RSS 减少约 137.2 MiB；父子合计 RSS 增加约 49.0 MiB。
- **钉钉：**主进程 RSS 减少约 7.8 MiB；父子合计 RSS 增加约 74.6 MiB。

子进程方案的主进程在全部样本中均未加载渠道 SDK。连接状态下，同进程飞书加载 10,059 个 `lark_oapi` Python 模块，钉钉加载 24 个所统计 SDK 模块；子进程方案对应模块位于子进程。模块数不是安装包数，也不直接等于内存大小。

两渠道子进程在全部连接样本停止后均已退出；同进程基线也返回 `stopped`、无停止错误，保留的渠道线程句柄确认已退出。关闭连接不会自动移除 Python 已导入的 SDK，所以同进程主进程 RSS 基本保留。子进程停止后可回收该进程；这不代表操作系统文件缓存或全部共享页面立即消失。

## 准备与连接耗时

| 渠道 | 方式 | 构造实例（秒） | SDK 加载至连接就绪（秒） | 停止（秒） |
| --- | --- | ---: | ---: | ---: |
| 飞书 | 同进程候选 | 1.372 | 1.171 | 0.001 |
| 飞书 | 子进程候选 | 1.345 | 1.379 | 0.013 |
| 钉钉 | 同进程候选 | 1.363 | 0.048 | 0.102 |
| 钉钉 | 子进程候选 | 1.371 | 0.513 | 0.017 |

构造时间包含真实构造方法触发的宿主延迟初始化，不是完整 QwenPaw 启动时间。同进程连接计时从测试网络边界导入 SDK 前开始；子进程从代理 `start()` 开始，包含进程创建、握手、SDK 导入及连接。网络为本地替身，不能据此比较真实平台网络延迟。两种方式的实例构造仍有公共宿主成本，本次没有改造这条初始化链。

副进程不是无成本优化：本次连接准备更慢、合计 RSS 更大。其收益是避免渠道 SDK 进入主进程、将渠道故障隔离、允许停用后回收整个渠道进程。正式网页能否更早可用，还取决于 A 接入时把核心就绪与渠道就绪分开。

## 方法、原始数据与复现

- 环境：`macOS-26.3.2-arm64-arm-64bit-Mach-O`，Python `3.13.10`；lark-oapi `1.7.1`、dingtalk-stream `0.24.3`、alibabacloud-dingtalk `2.2.53`。
- 同进程基线使用同一候选插件的 `channel.py`，子进程使用生产 Driver；插件复制到临时安装根，宿主公共代码及依赖来自同一已有环境。主进程公共支持模块和 pytest/pytest-asyncio 在两边预热，保留的测试桩记账开销仍存在，所以这是带观测代码的候选测量。
- 12 个连接样本之外，另存 12 个纯 Driver 导入诊断样本；后者不启动连接，不是原同进程 Channel 的启动指标。钉钉 SDK 延迟至启动加载，所以纯导入诊断的 SDK 模块数可为零。
- 使用 psutil 的当前 RSS，不使用峰值 RSS。未清操作系统缓存，三次样本不构成压力测试；没有测多工作区、真实吞吐、长期 CPU、正式网页/桌面/Docker。
- 原始 stderr 保留。飞书 SDK 有弃用提示；钉钉 SDK 会将正常取消连接记录为 `network exception`，需结合停止状态与线程检查判断。子进程 stderr 由现有执行器排空，不以宿主日志中没有警告证明子进程内部毫无警告。最终样本未出现管道 InvalidStateError 或被销毁的未完成任务提示。

[完整 24 个样本、版本、stderr 与测量源码摘要](2026-10-12-channel-process-measurements.json)。大范围 `preparation_seconds` 含两种测试装配的不同开销，仅保留作诊断，不作端到端速度比较。
