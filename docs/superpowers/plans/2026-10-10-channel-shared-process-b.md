# Channel 共享依赖、多进程实施计划

> **For agentic workers:** 使用 superpowers:subagent-driven-development 或 superpowers:executing-plans 逐项执行。功能代码和测试代码必须由不同子 agent 编写。复选框只记录已验证完成的工作；B1–B5 已完成，正式接入及 A/E 验证缺口仍待完成。

**Goal:** A 交付前，B 完成可独立验收的飞书、钉钉子进程及主进程代理；A 交付后集中接入插件安装、工作区启停、更新和正式渠道入口。

**Architecture:** 每个已启用的「工作区 × 渠道」实例拥有一个子进程，共用宿主的依赖安装环境。主进程读取静态描述，保留轻量代理、队列、ACL、审批决策和 Agent 执行；渠道专属代码、SDK、连接、媒体及卡片操作在子进程执行。优先复用现有 stdio + Content-Length + JSON-RPC。

**Tech Stack:** Python、asyncio subprocess、现有 channel_protocol、BaseChannel、lark-oapi、DingTalk SDK、pytest。

**Spec:** 依据 2026-10-10 会话确认的五条多进程原则和可行性评估；参考 [插件机制重构](../../插件机制重构.md#6-预留接口现在就留空协议)、[Core/Runner 边界](../../proposals/channel-isolation/CH-0-001_CORE_RUNNER_BOUNDARY.md)及[已有实施记录](2026-10-09-channel-pluginization-b.md)。原 isolation 的专属环境与独立更新事务不作为本次目标。

## 当前基线与分工边界

原步骤一至五已完成同进程候选插件、平台代码整理和行为测试。它们是本次迁移的功能基线；多进程验收需重新执行。原步骤六及其 1–2 天估计由本计划替代。

| B 可以独立完成 | 等 A 交付后集中接入 |
| --- | --- |
| 静态渠道描述、共享环境启动入口、进程监督、通信、Driver、轻量代理、候选包及进程测试 | 正式插件发现和登记、WorkspaceProjector 投影、Manager 启停、安装/更新事务、依赖关口、旧内置入口切换 |

独立验收直接调用真实代理、真实 BaseChannel 和真实子进程，用受控 Agent 回调与平台网络替身驱动。无需复制一套 PluginLifecycle，也不把 FakeApi 验收当成正式插件安装验收。

## 全局约定

- 首批飞书、钉钉；Console 留在主进程。沿用原渠道键、配置、会话、媒体及恢复记录。
- 沿用 `codex/channel-pluginization` 工作分支；实现精炼，功能与测试分工保持不变。提交/推送按用户后续指示执行。
- 渠道列表、静态校验和代理构造均不导入真实渠道类、平台模块或 SDK；启用才启动子进程。候选代码的探测导入也在子进程完成。
- 普通安装使用当前 Python；桌面版使用已有配套 Python 和可读取的共享依赖目录。显式传递可信代码/依赖路径，不假定父进程的 `sys.path` 或 frozen 包自动可见。
- 使用全新解释器入口，不继承主进程运行对象，不经过完整 CLI / Web 应用启动链。SDK 不在注册、探测或运行时自行装包。
- 平台初始化与连通状态分开；主进程代理的启动握手有超时，远端连接在后台准备。渠道失败不得卡住主进程事件循环。
- RPC 只传数据；实际操作者身份、回复目标、请求 ID 与实例代际必须保留。凭据不进入命令行、日志或持久启动清单；复用/补齐受控的一次性凭据传递。
- 队列、并发和日志有上限；超时不等于平台未发送。强杀后必须确认进程退出，未退出保留句柄、拒绝创建第二份实例；父进程退出也要回收所属进程。
- A 接入前保留当前正式入口。新路径通过独立宿主测试验证；不删除旧入口或默认 SDK，也不宣称整机内存、安装体积已经下降。

## 重点验收

1. SDK 已安装或测试全局替身掩盖主进程导入：B1、B3 在独立进程阻断真实平台导入。
2. SDK 卡死、崩溃、刷日志或父进程退出：B2 验证监督、超时、管道排空和进程回收。
3. 平台已发送但 IPC 回执丢失：B3、B4 验证 unknown 状态，不盲目补发。
4. 两工作区、重启后的旧消息及并发流式回复串线：B3、B4 验证身份、代际和回复路由。
5. 强杀、重启或共享依赖不可用导致旧配置/卡片读不到：B4、B5 验证数据兼容；正式升级恢复归 TODO-A4/A5。

- [x] 先用真实子进程覆盖缺 SDK、import 卡住、连接卡住、异常退出、刷日志、父进程退出和停止超时；主进程的独立协程持续可运行。
- [x] 实现同环境启动、协议握手、stdout/stderr 分离、持续排空、退出监听和有界重启退避；未启用不启动，显式停用禁止自动拉起。

- [x] 验证两实例互不影响，进程退出后没有所属连接、线程或孤儿进程；读配置/健康检查不启动新进程。

**公共组件边界：** 启动、通信、超时、退出监督和进程树回收只保留一份公共实现；频道描述、身份与平台连接状态由频道薄适配处理。公共组件只在调用方显式启动时创建进程，不因插件被发现或加载而启动。其他模块可直接提供入口和配置使用公共组件，无需伪造频道描述；安装、更新、依赖变更以及正式执行模式选择仍等待 A 接入。

### B3：跑通飞书 Driver 与主进程代理（1.5–2 天）

**涉及：** `plugins/channel/feishu/driver.py`、既有平台文件；新增 `src/qwenpaw/app/channels/isolated_proxy.py`；`feishu_process_suite.py`。

**产出接口：** `IsolatedChannelProxy` 提供宿主需要的 BaseChannel 调用面：`start/stop/health_check`、入队/请求转换、发送和流式钩子。它消费 B1 描述与 B2 进程句柄。Driver 接收现有 `channel.send`、停止/取消等数据命令，向主进程发送 `event.batch`；Agent 回调只存在于代理所在主进程。

代理通过 B2 的频道适配调用插件公共进程组件，不再自行创建另一套进程监督或通信实现。频道管理器决定何时启动实例；公共组件执行具体启停。

- [x] 从隔离方案飞书 Driver 复用可用边界，将步骤二、三已修复的收发、审批身份、重连和清理行为接入同一份平台实现；不回退自定义网关、旧路由和安全修复。

- [x] 实现轻量代理与 Driver；先覆盖私聊、群聊、旧会话，再覆盖媒体、审批、流式卡片、并发话题、主动发送和取消收尾。
- [x] 在主进程确认接收后去重入站消息；对已发出但回执丢失的操作保留 unknown。回复状态支持子进程重启恢复；不将会话合成身份当成真实审批操作者。
- [x] 跑原飞书行为基线及新增进程测试；宿主任务取消、平台断线、子进程退出分别验证，明确其对当次回复的影响。

**交付说明：** 静态入口为 `feishu.driver:FeishuDriver`，`code_root` 包含 `feishu/` 包；宿主显式创建 `IsolatedChannelProxy`，通过既有 `ChannelProcess` 使用公共执行层。普通任务、TaskTracker、主动发送、审批通知及合并媒体共用回复状态的收尾机制。入站暂时拒收最多重试五次，接收回执不明时保留回复路由；出站结果不明时不自动重发。完成的确定状态按数量和字节回收，未完成或不确定的状态保留，失败原因通过健康检查暴露。

**A 缺口：** 可用真实 BaseChannel + 受控 Agent 回调直接验收；正式工作区发现、启动与卸载投影在 TODO-A1/A2。

**实测结论：** 24 个样本覆盖两渠道、两种运行方式的连接及纯导入诊断。渠道 SDK 全部留在子进程，停止后子进程均退出；主进程 RSS 降低，但合计 RSS 和连接准备时间增加。收益是故障隔离与停用回收，不能据此宣称总内存或正式启动时间下降。方法、数据及复现见 [测量记录](2026-10-12-channel-process-measurements.md)，安装布局和框架接点见 [A 交接说明](2026-10-12-channel-process-handoff.md)。
